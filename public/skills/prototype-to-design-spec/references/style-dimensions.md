# 风格维度与候选差异矩阵

## 一、两轴定义

风格候选按两轴区分，缺一不可：

- **轴一：视觉流派**——用一句可感知的定位描述整体气质，负责让人能选。
- **轴二：token 轴**——用可量化、可写入 `design-tokens.json` 的变量描述差异，负责让选择能落成规范。

只有轴一没有轴二，选完只能得到「感觉」；只有轴二没有轴一，并排对比时用户无法形成整体判断。

## 二、token 轴清单

| 轴 | 变量名前缀 | 可量化内容 | 观察方式 |
|---|---|---|---|
| T1 主色与语义色 | `--color-` | 主色、成功/警告/危险/_DISABLED，色值与使用场景 | 主按钮、关键数值、提示条 |
| T2 中性色阶 | `--neutral-` | 背景、面板、分隔线、主文/次文/占位文字色阶数量 | 页面底色与文字层级 |
| T3 圆角 | `--radius-` | 卡片、按钮、输入、弹层四档圆角 | 卡片与控件边角 |
| T4 间距密度 | `--space-` | 基础步长、页面边距、组内/组间间距、信息密度档位 | 单位屏信息组数 |
| T5 字阶与字重 | `--font-` | 字号阶梯、行高、标题/正文/辅助字重 | 标题与正文对比 |
| T6 阴影与描边 | `--elev-` | 层级表达方式（浮起/描边/纯色分隔）、阴影强度 | 卡片边界 |
| T7 图标语气 | `--icon-` | 线性/面性、线宽、尺寸档、是否随语义着色 | 导航与操作图标 |
| T8 背景与卡片 | `--surface-` | 页面底色、卡片填充、是否使用渐变或纹理 | 大面积区域 |
| T9 状态与反馈 | `--state-` | 空/载/错/成功/禁用的表达强度 | 状态页与提示 |

其中 T3、T4、T6 属于**结构性差异轴**：它们改变页面的空间感与层级，最容易在并排对比中被感知。每个候选与其余候选至少在 3 个轴上明显不同，且其中至少 1 个为结构性差异轴。

## 三、候选方向起点（示例，非标准值）

下表为构建差异矩阵的**结构示例**，数值均为写作示例，标注「推导」；实际取值必须来自参考取样观察与项目推导，不得当作行业推荐值直接套用。

| 方向 | 一句话定位 | T1 主色 | T3 圆角 | T4 密度 | T6 层级 | 代价与风险 |
|---|---|---|---|---|---|---|
| A 克制极简 | 少色、少装饰、靠留白建立层级 | 单一强调色，语义色仅用于状态 | 小圆角 | 低密度、大留白 | 描边与分隔线为主 | 信息承载量低，长列表可能显空 |
| B 柔和亲和 | 低饱和浅色、圆润、轻卡片 | 低饱和主色 + 浅底辅色 | 大圆角 | 中密度 | 浅阴影浮起 | 对比度易不足，需校验可读性 |
| C 卡片分层 | 明确分组、信息密度高 | 中性底色 + 单强调色 | 中圆角 | 高密度 | 多层卡片 + 轻阴影 | 视觉噪声多，小屏易拥挤 |
| D 深色专业 | 深色背景、强数据对比 | 高亮强调色 + 克制的语义色 | 小圆角 | 中高密度 | 明度分层 | 需单独校验深底对比度与状态色 |
| E 手绘温度 | 柔和图形、拟人化语气 | 暖色系多辅色 | 大圆角/不规则 | 低密度 | 图形与色块分层 | 一致性维护成本高，业务感偏弱 |

> 以上方向仅为编排示例。项目可替换方向名称与数量（保持 4–5 个），但必须保留「差异矩阵 + 代价列」。

## 四、差异矩阵模板

```markdown
| token 轴 | A | B | C | D | E |
|---|---|---|---|---|---|
| T1 主色 | ... | ... | ... | ... | ... |
| T2 中性色阶 | ... | ... | ... | ... | ... |
| ... | | | | | |
| 结构性差异轴命中 | T4/T6 | T3/T4 | T4/T6 | T6 | T3/T4 |

每列至少 3 个轴与相邻候选不同；逐列核对后填写「差异可感知」结论。
```

## 五、与内容契约的映射规则

> **反面教材（真实发生）**：曾经把本节写成「复制原型首页 DOM，只覆盖 CSS 变量」，产出 5 张与原型构图完全相同的换色稿，被用户整体否决。不要重犯。

生成设计稿时执行：

1. 从 `prototype.html` 首页与 PRD 提取**内容契约**：信息项、文案、数值、状态、操作语义、tab 清单，以及需排除的原型评审道具。写入 `candidates.json → content_contract`。
2. 每个方向**独立重新构图**：头部形态、指标呈现、待办分组、快捷入口、空状态、底部导航、图形语言均可不同。HTML 结构不要求一致，也不应该一致。
3. 所有稿的 CSS 引用同一套命名前缀的 token（`--color-` / `--neutral-` / `--radius-` / `--space-` / `--font-` / `--elev-` / `--icon-` / `--surface-` / `--state-`），值由各方向覆盖，供 S3 抽取规范与 S5 反向约束。
4. 同一个主色必须区分**填充角色**与**文字角色**（如 `--brand` 与 `--brand-text`）。高饱和或深色主题下，直接把填充色当文字色会造成不可读数值，必须单独校验对比度。
5. 用 `scripts/derive_designs.py` 生成稿件与 `contract-check.json`，机器校验内容契约齐备；**不校验 DOM 一致**。
6. 为每个候选导出 token 快照（JSON），字段遵循 `assets/design-tokens.schema.json`。

## 六、不可观察轴的处理

9 个 token 轴不一定都能在首页观察到（例如原型首页没有图标时，T7 图标语气无法判定）。处理规则：

- 在 `02-style-references.md` 的差异矩阵下显式标注「该轴首页不可观察，留待 S4 组件层」，不得编造观察结论。
- 若某方向通过自绘图标使该轴变得可观察，需在矩阵中说明是设计稿引入的，不是从原型观察到的。
- 不可观察轴不得计入「每列至少 3 轴不同」的命中数。

## 七、自检

- [ ] 4–5 个候选，每个有明确的一句话定位与代价说明
- [ ] 差异矩阵完整覆盖 9 个 token 轴，不可观察轴已标注
- [ ] 每个候选与其他候选在 ≥3 个**可观察**轴不同，含 ≥1 个结构性差异轴
- [ ] **5 张稿并排缩小时构图明显不同**，不是同一张图换色
- [ ] 每个候选通过内容契约校验：信息项、文案、数值、操作、tab 无遗漏或改写
- [ ] 设计稿中无原型评审道具文案；图标与图形均为自绘
- [ ] token 值标注来源（取样观察 / 设计推导 / 用户指定），无「行业标准值」表述
- [ ] 并排对比页 `comparison.html` 能一屏看到全部候选的首屏
- [ ] 未替用户排序、未暗示唯一正确答案
