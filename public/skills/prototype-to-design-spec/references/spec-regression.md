# 否决回路、一致性回归与变更裁决

## 一、风格否决回路（S2）

用户在门禁 D 否决全部候选时执行：

1. **归因**：把否决理由归到 `references/style-dimensions.md` 的具体 token 轴（配色 / 密度 / 圆角 / 字阶 / 层级 / 图标 / 状态）或「参考样本不匹配」。不接受「就是不好看」作为可执行输入，需请用户用一句话指出最接近不满意的维度；用户无法指出时按「参考样本不匹配」处理。
2. **记录**：在 `04-style-decision.md` 追加本轮否决记录（轮次、全部候选编号、归因、用户原话要点），`design-state.json` 的 `rejection_rounds` 加 1。
3. **补样**：按 `references/reference-study.md` 补充取样，优先补归因维度的差异样本。
4. **重出**：回到 S1/S2，生成一组新的 4–5 个候选，保留历史候选与对比页，不覆盖。

### 收敛上限

**累计 3 轮**仍全部否决时，停止继续生成候选，改为输出「风格偏好澄清清单」，逐维度给出可选值请用户指定：

| 维度 | 可选值（示例结构） | 用户指定 |
|---|---|---|
| 主色倾向 | 冷色 / 暖色 / 中性 / 用户给色值 | |
| 信息密度 | 疏松 / 中等 / 紧凑 | |
| 圆角 | 小 / 中 / 大 | |
| 层级表达 | 描边分隔 / 浅阴影浮起 / 纯色块 | |
| 明度 | 浅色 / 深色 / 跟随系统 | |
| 图标语气 | 线性 / 面性 / 无图标 | |

用户逐项指定后生成最终一版候选并重新走门禁 D。禁止：无限重出、擅自把某一稿当作已选定、把沉默当作同意。

## 二、一致性回归（S5）

### 2.1 回归范围

- 对象：`01-entry-check.md` 页面清单中的**每一个** tab 稿 + 首页定稿
- 依据：`design-spec.md` 当前版本的全部 SP 条款 + `design-tokens.json` 当前版本
- 时机：组件层规范定版后、门禁 F 之前；任何规范或页面稿变更后必须重跑受影响范围

### 2.2 逐条判定表

```markdown
| 页面 ID | 条款编号 | 判定（通过/不通过/不适用） | 观察证据 | 处置 |
|---|---|---|---|---|
```

「不适用」必须写明原因，不得用「不适用」掩盖未检查。

### 2.3 缺口登记（S4 期间）

生成 tab 稿时遇到规范未覆盖的组件或状态：

```markdown
| 缺口编号 | 页面 ID | 缺口描述 | 临时实现（使用的现有 token） | 建议新增条款 | 状态 |
|---|---|---|---|---|---|
```

临时实现只能用已冻结 token，禁止静默新增色值、字号或间距档位。

## 三、冲突裁决

回归发现不通过时，二选一并留痕：

| 裁决 | 适用条件 | 动作 |
|---|---|---|
| **改稿** | 规范正确，页面实现偏差 | 修页面稿，重跑该页回归 |
| **改规范** | 规范在该场景确实不适用，且有明确边界 | 修订条款适用范围或新增豁免，说明不影响其他页面，重跑全部受影响页 |

禁止：为通过回归放宽判定条件、删除真实冲突、把不通过改标为「不适用」、只改结论不改产物。

### 变更评估五要素

```markdown
| 变更请求 | 影响范围 | 产物改动量 | 风险变化 | 干系人 | 结论（纳入当期 / 记后续版本） |
|---|---|---|---|---|---|
```

规范版本演进规则：`v0.1` 基础层冻结 → `v0.2+` 组件与状态层扩展 → `v1.0` 设计基线冻结。每次变更写清「新增/修订/废弃的条款编号」与「需回归的页面清单」。

## 四、`07-spec-regression.md` 结构

```markdown
## 1. 回归范围与依据版本
## 2. 逐条判定表
## 3. 缺口登记与处理结果
## 4. 冲突与裁决记录（含变更评估表）
## 5. 规范版本演进
## 6. 否决回路记录（轮次、归因、收敛结论）
## 7. 未解决冲突数 / 未解决缺口清单
## 8. 结论
```

`design-state.json` 的 `unresolved_conflicts` 必须与此文档第 7 节数字一致；非零时门禁 F 不得通过。

- [ ] 判定条件未被放宽，产物与结论一致

- [ ] 规范版本演进与 `design-spec.md` 变更记录一致
