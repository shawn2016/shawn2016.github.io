# 参考取样与风格学习规程

## 一、目的与边界

把第三方真实产品界面当作**风格特征样本**，而不是可复制的素材。本规程只产出文字化的风格观察，用于支撑 `02-style-references.md` 与 S2 的候选方向归纳。

**禁止**：把参考截图、图标、界面文案、品牌标识、配色板原样搬进任何交付物；把参考站数据当作「行业调研结论」；把某个产品的做法写成强制标准。

## 二、默认参考源

首选 UI Notes（https://uinotes.com/），定位为「真实产品 UI 设计灵感库」，收录上线产品的完整界面截图，含 App 库、截图库、公司与行业筛选、AI 搜图。首页公开可见应用数与截图总数，登录后可用更多筛选与搜图能力。

参考源不唯一。同类产品官网、公开设计案例、系统平台设计规范都可作为补充，但每条样本必须写明来源链接与取样时间，并区分「已查证事实」与「参考观点」。

## 三、浏览器协作

1. 用 ego-browser 打开参考站；需要用户登录时，先交还浏览器控制权，明确告知「请在窗口完成登录后回复」。
2. 用户确认后恢复**同一个任务空间**，不新建空间、不丢弃已打开页面。
3. 只读取完成风格判断所需的最小页面状态：优先用 DOM 提取筛选条件与条目列表，需要视觉判断时再截图。
4. 取样截图保存到系统临时目录，标注仅用于内部学习，**不写入 `design/` 交付目录**。
5. 遇到付费墙、验证码、权限提示时停止自动化尝试，交还用户处理，不绕过限制。

## 四、取样规程

### 4.1 同类筛选

按 `01-entry-check.md` 锁定的产品形态与行业挑选样本，优先满足：

- 与目标产品同平台（小程序 / iOS / Android / Web）、同信息层级（工具型 / 内容型 / 交易型）
- 包含至少一个「高频主页面」和一个「表单/编辑页」，避免只取营销首页
- 覆盖不同视觉取向，避免 5 个样本全来自同一家公司的同一套设计语言

### 4.2 数量下限

| 项 | 下限 |
|---|---|
| 参考产品 | ≥5 个 |
| 每个产品的关键界面 | ≥3 张（首页/主列表、详情或编辑、状态或反馈） |
| 样本总数 | ≥12 张 |
| 归纳出的风格方向 | 4–5 个 |

数量下限是**观察充分性**要求，不是「看得越多越好」。达到下限且风格特征开始重复时即可停止取样。

### 4.3 每条样本的记录表

```markdown
### 样本 S-01
- 来源链接：
- 页面/条目标识：（App 名 + 界面名或截图编号，不贴图）
- 取样时间：YYYY-MM-DD
- 界面类型：主列表 / 详情 / 表单 / 空状态 / 反馈
- 风格特征：
  - 配色关系：（主色与背景的关系、语义色数量、大面积色块有无）
  - 信息密度：（单位屏内信息组数、留白节奏、分隔方式）
  - 圆角与描边：（量级描述，如「大圆角卡片 + 无描边」）
  - 字阶与字重：（层级数量、标题与正文的对比强度）
  - 图标语气：（线性/面性、粗细、是否有色彩）
  - 卡片与层级：（浮起/平铺、阴影强度、分组方式）
- 可借鉴点：（只写通用手法）
- 明确不借鉴点：（专有内容、品牌特征、不适用原因）
- 已查证事实 / 参考观点：（分列）
```

### 4.4 归纳输出

`02-style-references.md` 末尾必须有「风格方向归纳」表：

| 方向 | 一句话定位 | 支撑样本编号 | 在两轴上的差异 | 适用代价与风险 |
|---|---|---|---|---|

方向命名用可感知的中性词（如克制极简、柔和亲和、卡片分层、深色专业、手绘温度），不使用「最好看」「最专业」等绝对化或不可判定的表述。每个方向至少关联 2 个样本，且与其他方向在 `references/style-dimensions.md` 的至少 3 个 token 轴上存在明显差异。

## 五、补充取样触发条件

出现以下情况时回到本节补取样本，并更新 `02-style-references.md`（追加，不覆盖历史）：

- 门禁 D 用户否决全部候选，且否决理由指向「参考不够 / 方向不对」
- 现有样本无法覆盖某个待归纳的 token 轴
- 目标产品有样本未覆盖的界面类型（如日历、统计图表）

补取时优先补**差异维度**，而不是简单地多截几张同风格图。

## 六、合规自检

- [ ] 交付目录内没有第三方截图、图标、文案、品牌复刻
- [ ] 每条样本有来源链接与取样时间
- [ ] 观察文字为原创描述，非复制参考站的介绍文案
- [ ] 未把参考站统计数字当作调研结论写进规范
- [ ] 未使用绝对化用语与广告法违禁词
- [ ] 登录、付费、权限相关操作均由用户本人完成或明确授权
