# Dispatch Advisor

## 核心原则

1. **默认自主**：大多数任务（查资料、写文档、拆任务、审代码、改配置、小改动）WorkBuddy 直接干，不需要问。
2. **只对"重活"请示**：只有任务属于外部引擎更合适、且工作量不小（预计 > 10 分钟 或 涉及 3+ 文件 或 用户点名引擎）时才询问。
3. **问了就给建议**：询问时必须给出推荐引擎 + 理由 + 可直接执行的命令，让用户一句话拍板。
4. **用户拍板后无条件服从**：用户选哪个就执行哪个；用户说"你自己来"就自主执行，不再反复确认。
5. **执行引擎时 WorkBuddy 仍负责管理**：拆任务、写 context、验收都是 WorkBuddy 的活。

## 外部引擎能力速查

| 引擎 | 命令 | 擅长 | 备注 |
|---|---|---|---|
| Cursor CLI | `agent -p "..." --output-format text` | IDE 集成、代码补全、改多文件 | 需先 `agent login` 或 CURSOR_API_KEY |
| Codex CLI | `codex exec "..."` | 架构设计、重构分析、探索代码 | 需登录 |
| Claude Code | `claude -p "..." --output-format text` | 复杂代码生成、写测试、修 Bug | 需登录或 API Key |
| WorkBuddy 自己 | 直接做 | 规划、文档、审核、协调 | 默认 |

## 判断矩阵：什么时候该请示

### 应该请示（外部引擎更合适）
| 任务类型 | 推荐引擎 | 理由 |
|---|---|---|
| 大型重构（多文件、跨模块） | Codex | 架构级思考、改多文件稳定 |
| 复杂算法/系统设计 | Codex | 深度推理、全局视野 |
| 大量单元测试 | Claude Code | 擅长测试生成 |
| 复杂代码生成 | Claude Code | 代码生成质量高 |
| 需要 IDE 诊断/补全/逐文件导航 | Cursor CLI | IDE 集成强（需先认证） |
| 用户主动点名引擎 | 用户指定 | 用户意图优先 |

### 不要请示（WorkBuddy 直接干）
| 任务类型 | 原因 |
|---|---|
| 查资料、搜索、读文档 | WorkBuddy 自带联网 |
| 写报告、写方案、拆任务、审代码 | WorkBuddy 本职 |
| 改配置、小修小补（< 3 文件） | 外部引擎启动开销不划算 |
| 需要连接器的任务（浏览器/数据库等） | 外部引擎没有这些工具 |
| 多 Agent 协作编排 | WorkBuddy 核心能力 |

## 询问流程（标准模板）

动手写代码前，用以下格式确认：

```
【任务分诊】这个任务用哪个引擎更好，请你拍板 👇

📋 任务：<一句话描述>

🤔 我的判断：<理由，为什么外部引擎更合适>，交给 <推荐引擎> 做更稳。
   我仍会负责拆任务和验收，只是执行交给它。

🗂 选项（直接回复数字或名字）：
   1. 用 Codex 执行（推荐）—— <理由>
      > codex exec "<prompt>"
   2. 用 Claude Code 执行 —— <理由>
      > claude -p "<prompt>" --output-format text
   3. 用 Cursor 执行 —— <理由>
      > agent -p "<prompt>" --output-format text
   4. 你自己来（WorkBuddy 直接做）
```

执行规则：回复 1/2/3/4 或引擎名 → 立即执行；用户没回复 → 视为选 4；询问一次，不连环问。

## 派活执行细节

1. 拆任务写 `tasks/<name>/plan.md`
2. 写项目上下文 `tasks/<name>/context.md`
3. 调外部引擎执行（命令里带 plan/context 路径）
4. 完成后检查产物、跑测试、验收
5. 不通过 → 反馈重做；通过 → 更新任务状态

## 一句话总结

> 大多数任务直接做，别问。只有当任务明显更适合 Cursor/Codex/Claude Code 执行时，
> 动手前用【任务分诊】模板问一次用户、给推荐、给命令，用户拍板后无条件执行。
> 用户的拍板优先于所有默认规则。
