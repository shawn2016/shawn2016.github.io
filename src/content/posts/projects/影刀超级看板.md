# 影刀·超级看板

> 一个基于影刀（ShadowBot）的公司类型触发器流程：把监控触发、文件创建触发、重启触发串起来，服务化对外提供 API。

## 背景

原本的流程靠人工点、靠手动传文件，状态不可观测。目标是把"触发 → 执行 → 回执"变成一条可查询的链路。

## 架构

| 层 | 组件 | 职责 |
|---|---|---|
| 接口层 | uvicorn / Python ASGI | 提供查询 / 触发 / 完成三类 API |
| 编排层 | 触发器 + 状态机 | 监控、文件、重启三类触发统一入口 |
| 执行层 | 影刀客户端 | 实际 RPA 执行，产出截图与日志 |
| 观测层 | 日志 + 追踪 | 每次执行可回溯，证据优先 |

## 关键决策

1. **输出结构化**：公司信息统一返回纯 JSON（类型 / 行政级别 / 行政地区），不夹带说明文字，方便下游直接消费
2. **触发幂等**：同一任务重复触发不产生重复副作用，靠任务 ID 去重
3. **证据优先**：验证不只看 RPA 返回，还要比对截图 + OCR 结果，避免"跑成功但结果错"

## 踩过的坑

- 内网 Windows 的盘符映射和路径大小写不统一，统一改绝对路径后稳定
- 服务重启后未清理上一轮锁文件，导致首轮触发被吞（已加入启动自检）
- 监控触发频率过高时与影刀客户端抢资源，加了退避
