# 给个人域名接一台服务器：一次从 DNS 到反向代理的复盘

手里有个域名，想在上面放几个自己用的工具服务。看起来是件小事：解析一下、连上服务器、把服务丢上去。真做起来才发现，每一步都有一个「你以为它做、其实它不做」的错位。

这篇把今天的操作从头记一遍，重点不在某台机器的参数，在三个反复踩到的判断错位。具体账号、密码、公网 IP、手机号一律不落地，用尖括号占位；想知道真值去私有记录里查，这篇只负责流程。

## 一条先说在前面的判断

**DNS 只负责把一个名字指到一台机器，不负责端口；登录方式由操作系统决定，不由你的习惯决定。**

这两句听着像常识，但它们正好是今天两个卡点。想要的效果是「访问 `子域名.<域名>` 就直接打开我跑在 3000 端口的服务」，于是在 DNS 里找了半天「端口」该填哪——没有这一栏。DNS 里那条 A 记录只能写 IP。要让域名直达端口，得在服务器上再架一层反向代理。

另一句同样直接：想用 SSH 登录，但买的是 Windows 镜像的机器。Windows 默认没有 SSH 服务，登录走远程桌面。工具换成任何一家云厂商、任何一个面板，这两条判断都不变。

## 完整步骤

按实际执行顺序记，每步都对应上面的判断。

### 1. 先把域名和目的定下来

域名是之前挑好的：首年便宜、续费也便宜、不带个人名、读着像正经平台。选后缀时避开了「首年 1 元、续费 169」那类坑，最终定在一个续费几十块的 `.cn` 上。

用途先写清楚——放自己用的工具站。这一句决定了后面所有选择：要能绑自定义域名、要能建数据库、要能长期续得起，不需要多用户和计费系统。

### 2. DNS 加一条 A 记录

在域名解析控制台，给要用的子域名加一条 A 记录，指向服务器的公网 IP。主机记录填子域名前缀，记录类型选 A，记录值填 `<公网IP>`。

这一步只做完了一半。它保证了「这个名字能找到这台机器」，不保证「这个端口有东西在听」。记完这条就要转身去服务器那头。

验证用命令行最快：`nslookup <子域名>` 应该返回你填的 IP。解析是否全球生效要等一会儿，本机这一步通常立刻就能查到。

### 3. 摸清服务器的底细，别急着操作

连之前先在控制台看清楚三件事：什么系统、什么配置、防火墙开了哪些端口。

这次一看发现是 Windows Server，内存只有 2GB，而且已经用掉八成多。这两个信息直接改了后面的计划：登录方式从 SSH 改成远程桌面，装环境从「全套 LNMP」改成「只装 Web 服务器和数据库」。

**低配机器先算内存账，再决定装什么。** 面板组件、PHP、管理界面每一样都要吃内存，装完才发现跑不动就得回头卸。

防火墙那头确认放通了几个固定端口：远程桌面的、面板的、Web 的 80/443。缺哪个补哪个，但只补这一趟真要用到的。

### 4. 登录：远程桌面进系统，面板管站点

控制台自带网页终端，选远程桌面协议连进去。Windows 的 Administrator 密码如果是自己设的，直接用；忘了就在控制台走重置密码流程，重置后要重启才生效。

进去之后看到的不是一个空系统——机器上已经装了宝塔面板，图标就在桌面。面板的初始地址、账号、密码写在首次启动的信息窗口里。这三样记到私有记录里，别留在公开笔记。

登录面板时踩了两道门：图形验证码，以及绑定厂商官网账号。**绑定账号是面板的强制步骤，跳不过去**，但页面明确写了它不授予别人接管服务器的权限，不是后门。这里有个人为失误：先在官网注册登录了一遍，以为就完事了，其实面板这一端还要用同一个账号再填一次才算绑定。两边是分开的。

### 5. 装环境：只装要用的

面板首页有「一键安装套件」，默认勾选一大串：Web 服务器、数据库、FTP、脚本语言、数据库管理界面。全勾上在 2GB 内存的机器上太重，而且这次用不到脚本语言和数据库管理界面——面板自己就能建库管库。

于是只留了 Web 服务器和数据库两项，取消其余，再点安装。中途任务队列卡在「等待」不动，面板自己给了提示：点「重启服务」重置任务队列。点了之后立刻恢复，下载、解压、安装一路跑完。

**装之前先看一眼默认勾选项，别让一键安装替你决定这台机器要跑什么。**

### 6. 建反向代理：把域名和端口接起来

面板的网站页里有专门的「反向代理」分类，比普通站点少绕一圈。添加反代要填三样：

- **域名**：`<子域名>.<域名>`，也就是 DNS 里解析的那条。
- **目标 URL**：`http://127.0.0.1:3000`。这是关键——填的是本机回环地址加服务真正监听的端口。
- **发送域名**：保持默认的 `$http_host`，把原域名透传给后端。

填完提交，列表里出现一条记录，指向刚填的目标。此时状态多半显示「未部署」或「502」，这是对的——后端 3000 端口还没有服务在跑。

### 7. 验证：分开测链路的每一段

不要等所有东西都好了才一次性验收，那样出问题不知道断在哪。分段测：

1. 测 DNS：`nslookup <子域名>`，确认解析到对的 IP。
2. 测 Web 服务：访问 `http://<子域名>`，看响应头里有没有 `Server: nginx` 之类的标识。有，说明请求已经到了服务器上正确的程序。
3. 看返回码：此刻返回 502 是预期的，它证明前两段都通了，只差后端服务没起来。

**502 不是失败，是链路走通的证据。** 等 3000 端口的服务起来，502 会自己变成网站内容。

## 这次涉及的凭据，都在哪

这篇不写任何真值，只记「有哪几样、分别在哪找回」。后续的人或 AI 照这个清单去私有记录里取。

| 凭据 | 用途 | 找回方式 |
|---|---|---|
| 服务器系统密码 | 远程桌面登录 | 自己设的用自己记的；忘了在云控制台重置，重启后生效 |
| 面板地址（含端口和入口路径） | 打开管理面板 | 首次启动信息窗口；忘了用面板自带命令查 |
| 面板账号与密码 | 登录面板 | 同上；密码乱了用面板命令重置 |
| 厂商官网账号 | 强制绑定面板 | 注册时用的手机号或邮箱 |
| 子域名与公网 IP | DNS 记录和反代 | 域名解析控制台 |

原则很简单：**公开笔记只记流程和占位符，真值只进私有记录。** 这篇能被索引、被别人搜到，所以哪怕是真值的片段也不能漏进来。

## 还没做的事

- 服务还没部署到 3000 端口，部署完回来复测，502 应该消失。
- 数据库这次没建。等表结构定了，在已经装好的数据库里建库和专用账号，记下连接信息。
- 面板还在用默认端口和 HTTP 明文，面板自己也弹了安全警告。有空改端口、开面板 SSL。
- 域名要长期绑国内服务器对外服务，需要做 ICP 备案；只做跳转或先用海外服务器可以缓一步。
- 自动续费按需要关掉，避免到期按原价自动扣款；顺手开域名隐私保护。

## 一条带走的判断

**把「域名到服务」拆成 DNS、反向代理、后端服务三段，出问题先定位断在哪一段，别整条重来。** DNS 只认名字和 IP，端口归反向代理管，登录方式归操作系统管——三个职责互不越界。拆开之后，502 这种看起来像报错的东西，反而成了前两段已经通了的证据。

再补一句给未来的自己：低配机器做任何安装之前，先看内存余量，再决定装几个组件。省下来的不是钱，是排查「为什么卡死」的时间。
