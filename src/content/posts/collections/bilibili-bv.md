先说场景。

想把《Fate/Zero》第二季最后一集存进稍后读、用命令行工具下载、或在别的文章里引用，你需要的是 BV 号——B 站普通视频那套 `BV11q4y1677C` 编号。但番剧给你的全是另一套：`b23.tv/ep13874` 短链、`/bangumi/play/ep13874` 剧集页。地址栏从头到尾不出现 BV。

B 站 2020 年 5 月就有人发布教程视频教这个换算，需求一直都在。做法可以照抄，但值得把判断抽出来。

## 判断：资源有多套编号，页面只展示一套

平台大一点的资源，编号几乎都不止一套。B 站一个番剧剧集至少有三个：BV 号（新体系）、AV 号（旧体系）、以及番剧剧集的 ep 号。三套编号指向同一个视频，但页面按场景只展示其中一套——番剧页给你 ep，普通视频页给你 BV。

所以「在番剧页面上找 BV 号」这个动作本身就不成立。缺的不是眼力，是两套编号之间的换算表；换算表通常不在页面上，在平台的 Web API 里。

这条判断离开 B 站依然成立：GitHub 的 PR 有编号也有 commit SHA，YouTube 有视频 ID 也有播放列表项 ID。跨体系取号时，先问「这个平台的编号映射接口在哪」，比扒页面快得多。

成立条件是平台有公开（或半公开）的 Web API。B 站满足，而且不挑登录状态——这是下面方法的前提，也是它随时可能失效的软肋。

## 实操：五步对出 BV 号

以《Fate/Zero 第二季》第 25 话（`b23.tv/ep13874`）为例，全程不用登录：

1. **取 ep 号**：短链 `b23.tv/ep13874` 里的数字就是；或打开页面看地址栏 `/bangumi/play/ep13874`。
2. **请求季信息接口**：`https://api.bilibili.com/pgc/view/web/season?ep_id=13874`，浏览器或 `curl` 直接访问，返回一段 JSON。
3. **在 `episodes` 数组里找 `ep_id` 等于 13874 的那一项**。一个季通常十几项，逐项对号。
4. **读 `bvid` 字段**——在这项 JSON 里正好倒数第二个，值是 `BV11q4y1677C`；旁边的 `aid` 就是旧 AV 号 `591845175`。
5. **验证**：打开 `https://www.bilibili.com/video/BV11q4y1677C`，应跳到同一集；不放心再调 `api.bilibili.com/x/web-interface/view?bvid=...` 对标题。

## 同类方案对比

| 方案 | 编号从哪来 | 要登录吗 | 能拿到什么 | 失效先兆 |
|---|---|---|---|---|
| 番剧页地址栏 | 页面 URL | 否 | 只有 ep 号和季编号 | 番剧改版换 URL 规则 |
| 第三方短链解析站 | 解析 b23.tv 跳转 | 否 | 跳转目标仍是剧集页 | 站点关停 |
| stat 接口反查 | `archive/stat?bvid=` | 实测未登录被拦 | BV 号 + 精确到个位的硬币/弹幕 | 登录墙（已发生） |
| season 接口对表（本文） | `pgc/view/web/season` | 否 | ep↔BV↔AV 全量映射 | 同门已拦，自己尚未 |

按成立条件选：

- 只要 BV 号、偶尔查几次 → season 接口，零成本。
- 要精确统计（硬币、弹幕到个位）→ stat 接口，但要在浏览器登录后访问。
- 资源没有 Web API 的平台 → 只能回到页面人肉换算。

风险照实说：season 是未文档化接口，没有任何稳定性承诺。同一个 API 家族里，stat 接口 2026 年 11 月实测已经对无 cookie 请求返回错误页。今天的零登录五步，随时可能多出一步「先登录」。频率上收敛点，别拿它批量爬；区域版权也会通过返回里的 `area_limit` 字段拦掉部分剧集。
