先说一个场景。

桌上一台 Mac、一台 Windows，一套键鼠。想让两台机器共用它，二十年来的答案没变过：要么伸手去按硬件 KVM 的按钮，要么装 Synergy、Barrier 这类软件，然后在配置里指定一台机器当服务器。

服务器不是随便选的，它是整个组网的中心：主机挂了，副机的输入跟着断；换一台主力机，配置要重排一遍。软件还在更新，架构停在了 2001 年。

这篇想把判断往前挪一步：**挑共享外设类工具，第一问不是功能列表，是它把「中心」放在哪**。中心在哪，故障半径就在哪；信任从哪来，决定你敢不敢把它放进局域网。

[Oink](https://github.com/oinkvm/oink) 是这个判断的一个极端样本。Oink Is Not only a KVM，Rust 写的软件 KVM，只做 Mac 和 Windows。2026 年 10 月 19 日建库，25 天拿到约 1500 star，11 月 8 日到 11 日连发 0.3.4、0.3.5、0.3.6 三版。

## 把中心删掉之后，剩下什么

它没有客户端和服务端的概念。键盘接在哪台机器上，那台机器就能控制其他所有设备；反过来也一样。仓库 FAQ 写得很直白：不需要指定一台设备当控制器，用的是自研的对等协议，不与其他软件 KVM 兼容。

删掉中心换来的东西很具体。设备列表的排序是全组共享的，在任何一台机器上拖动都会同步到所有机器；「指针切到下一台设备」的快捷键，不依赖哪台机器活着才生效。

代价也真实：没有中心，就没有一个天然的「权威」。谁来证明一台新设备有权加入？这就要说到它最值得拆的部分。

## 信任从「账号」挪到「在场」

Synergy 这类软件的信任模型是配置信任：把 IP 和密钥写进配置文件，配置对了就通。Oink 的配对走 SPAKE2——两台设备各出一方，靠一个 6 位数字码完成密钥协商；协议源码里，会话密钥全程带零化处理（zeroize），用完即清。

6 位配对码的本质是一条物理约束：**配对成立的瞬间，两台设备的人要在同一张桌上**。中心服务给的信任是「你是谁」，靠登录账号证明；对等配对给的信任是「你在哪」，靠同一局域网、同一时刻、共同看着屏幕证明。日常流量默认全程加密，配对码错了协议直接终止。

这条判断有成立条件：同一个人的几台设备、同一个局域网。换成大团队或跨网段场景，在场信任反而成了负担——每台新设备都要人到现场。工具没变好也没变坏，是场景换了判据。

## 方法论之下，功能是怎么长的

功能不按模块列表来，按「删掉中心之后要补什么」来：

1. **输入要自己找路。** 鼠标滑过屏幕边缘就切到下一台设备，像多接了一块扩展屏；键鼠之外还共享触控板手势——Windows 端没测过，README 自己承认了。
2. **没有中转服务器，数据就得在设备之间直接走。** 剪贴板自动同步，文字、图片、文件可以从一台机器拖到另一台，甚至拖进 Chrome 这类普通应用里。
3. **音频也进了同一张网。** 几台机器的声音能从一台设备的音箱或耳机里出，麦克风做成虚拟设备共享。这类功能在传统 client-server KVM 里基本不存在，因为它们假设要共享的只有键鼠。

工程结构也值得看一眼：Rust workspace 拆了 15 个 crate，协议、组网（发现、配对、QoS）、输入、显示、剪贴板、音频、Windows 服务各自成块；界面用 Tauri 2 做成托盘应用；macOS 的拖拽入口用了 Finder Sync 和 File Provider 的 Swift 扩展。约 1800 万字节 Rust、180 万字节 TypeScript，Rust 2024 edition。

## 从零跑通，大概要几步

按使用顺序记一遍，每步都对得上前面的判断：

1. **两台机器都装上。** 从 GitHub Releases 下载：Mac 是 dmg，要求 macOS 14.2+；Windows 是 msi，要求 Win10 1809+。装完它就是个托盘应用，常驻后台。
2. **组网不用配 IP。** 同一局域网内设备会自动出现在「附近设备」列表；搜不到时检查两边防火墙，或者手动输入对方的 IP——界面上就留了这个入口。
3. **配对是双向确认 + 6 位码。** 一方发起连接，另一方屏幕上显示 6 位数字码，回输到发起方这一侧就完成。对话框上写着一句提醒：完成配对后，对方可以远程操控本机。所以配对码别念给不相干的人；拉黑过的设备会被自动拒绝，也不再出现在附近列表里。
4. **日常用法是「滑过去」。** 鼠标滑过屏幕边缘就切到下一台设备，像多接了一块扩展屏；不喜欢滑边缘的，去设置里开「切换指针位置」快捷键（默认关闭），一键跳到设备列表的下一台。设备列表的排序全组共享，在哪台机器上拖动都一样。
5. **剪贴板和文件不用设置。** 复制了就能在另一台粘贴；把文件夹从 Mac 拖到 Windows 时会顺手清掉 .DS_Store；拖过来的文件都收在「接收文件」区，可以管理、删除。
6. **音频要指定出口。** 挑一台机器「设为音频出口」，其他设备的声都从它那里出；共享麦克风有全组统一的静音开关；音质档位往上调会吃延迟和带宽，视频会议场景建议默认档。

六步里没有一步要求注册账号、填许可证或者指定哪台是主机。这本身就是那个判断的延续：中心删掉之后，配置量也应该跟着删。

## 同类方案怎么选

对比不按功能打分，按前面那条判据来：**中心在哪、信任从哪来、要共享的东西给到多远**。

| 方案 | 中心在哪 | 信任从哪来 | 剪贴板 | 拖拽 | 音频 | 覆盖平台 |
|---|---|---|---|---|---|---|
| 硬件 KVM | 无（物理线） | 线插对了就是它 | 无 | 无 | 看型号 | 不限 |
| Synergy 系（Deskflow / Input Leap） | 主机当服务器 | 配置文件 | 有 | 无 | 无 | Mac / Win / Linux 最广 |
| Logitech Flow | 罗技外设本体 | 罗技账号绑定 | 有 | 有（文件） | 无 | Mac / Win |
| PowerToys Mouse Without Borders | 主机当服务器 | 配置密钥 | 有 | 无（文件走复制粘贴） | 无 | 仅 Windows，最多 4 台 |
| Apple 通用控制 | 无 | 同一 Apple 账号 | 另走通用剪贴板 | 有 | 无 | 仅 Mac / iPad |
| Oink | 无 | 配对瞬间，同一张桌 | 有 | 有（文字/图片/文件） | 有 | Mac / Win |

没有一列是全赢的，选型就是拿成立条件套自己：

- 全是 Mac 加 iPad：先试系统自带的通用控制，别装任何东西。
- 全是 Windows：PowerToys 的 Mouse Without Borders 够用，免费、微软出品。
- 有 Linux 机器、或者要一个稳定了十年的成熟方案：Deskflow 系，它服务端中心架构换来的是最广的平台覆盖。
- 鼠标键盘都是罗技：Flow 顺手，但被品牌绑定。
- Mac + Windows 混合、还想要音频聚合：Oink 几乎是唯一解——剪贴板、拖拽、音频、触控板手势在一套对等网络里全给了。
- 要接游戏主机、进 BIOS、或者网络环境不可信：回到硬件 KVM，物理层的东西不讲信任模型。

Oink 的风险也要摆在这张表旁边：项目只有三周半，平台只两家，Intel Mac 没测过，作者不收 PR 意味着修复节奏取决于一个人加一个 AI。「唯一解」和「稳定解」不是一回事，这是换判据的时候最容易忽略的一条。

一个人，三周半，约 1800 万字节 Rust，1500 star。AI 在这个项目里不是营销词，是写进了工作流的生产资料——作者默认每个来报 issue 的人都已经让 AI 排查过一遍。

## 边界和代价

- GPL-3.0 加附加条款：改了自用随便，分发衍生产品不能用 Oink 这个名字。
- 不收 PR，只收带诊断数据的 issue。
- 只支持 macOS 14.2+ 和 Windows 10 1809+；Intel Mac 标注「未测试」；Linux 不支持——依赖配置里明确写了非这两家系统只编译平台无关的部分，连 CI 都不为 Linux 装 WebKitGTK。

## 本次采集学到的判断

判断共享类工具，先看两件事：中心在哪，故障半径跟着中心走；信任从哪来，账号信任证明你是谁，在场信任证明你在同一张桌上。这个判断反过来用也好使：一个宣称「去中心」的工具如果开始悄悄要账号，它要补的多半不是功能，是权威。
