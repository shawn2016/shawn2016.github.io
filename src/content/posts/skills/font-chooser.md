上一轮我把 230 款开源字体整理成清单，交给模型自己选。给一张海报挑标题字体，它选了得意黑，理由写得挺完整：倾斜、有冲击力、适合海报标题。

看着没问题。但那句话是从 `useCases` 标签里读出来的，不是看出来的。同一份清单里，「寒蝉正楷」被标成了「英文长文」。

问题不在模型不认识字。是我给它的证据只有形容词。

## 形容词验收不了

「圆润」「有力量」「复古」这些词，模型能生成，也能复述，但没法核对。我说「再大气一点」，它把字重从 400 换成 700，跟人说「再高级一点」就把圆角从 12 改到 16 是一回事。

字体比配色更难的地方在于，字形之间的差异没法写成参数。宋体的三角收笔、得意黑的倾斜压缩、站酷快乐体歪歪扭扭的数字，落到文字里都只剩「有特点」。

所以这里要反过来说一次：**让 AI 选字体，缺的从来不是字体清单，是一张能看的脸。**

但光有脸也不够。看中一款却贴不出代码，选择就停在感想。一次合格的选字得同时交出两样东西：一个可指认的图片编号，和一行能运行的引用代码。两者靠同一个 `id` 对齐。

这个判断有成立条件：模型产出的是 HTML / CSS 设计稿代码。若模型直接生成图片，字形不由 CSS 控制，图册只能当风格参考。

## 两个动作，一个连接点

把「选字体」拆开，每一步都有交付物。

**看图判断。** 15 页样张，每页 9 款，同一句话用不同字体真实渲染。卡片上有名字、id、风格，还有一行带数字和标点的小字。中文好看但数字难看的字体，排价格、日期的版面会翻车，这一行就是用来验收的。

**查表落地。** 选中之后按 id 查到 `cssFamily` 和 CSS 地址，贴一行 link 即可，不需要 API Key。

连接点是 `id`。图册、清单、引用代码共用同一套 id，才不会「看中第 12 页那款，贴出来的是另一款」。

检验这套方法是不是产品说明书，用本站那篇《采集类文章写作框架》里的办法：把字体酱换成另一套开源字体库，文章还成立吗？成立。它规定的是证据的形式（图 + id + link），不是哪 230 款字体。

![四款字体对照：思源黑体、思源宋体、得意黑、站酷快乐体](/attachments/font-compare-4.png)

四张卡片里，第二张有衬线，第三张倾斜，第四张连数字都不规则。这些差异写进文字都会退化成形容词，摆在一起却一眼可辨。

## 图册怎么来的

字体酱没有预览图接口。它的「预览」是拿字体实时渲染文字，不是图片。网上现成样张又都是逐款分散的页面，没有统一入口，喂给模型不好用。

只能自己生成。它的分片 CSS 是一份索引：289 个 `@font-face`，每个用 `unicode-range`（CSS 里声明这个字体文件覆盖哪些字符码点）指向一个小 woff2 分片（网页字体的压缩格式）。免 Key，跨站可用，缓存一年。

关键取舍是不下载整套字体。样张只有二十来个字，按 `unicode-range` 反查，每款只需要 7 到 12 片，把它们 base64 内联进一个 HTML，交给无头浏览器（不带界面的 Chrome）截图。整套原字体约 15 MB，落地的 15 张 PNG 一共 4.4 MB，1304 个分片缓存完，全量出图两分钟。

内联不是洁癖。无头浏览器的虚拟时间会跳过真实网络等待，直接引用远程 CSS 时，截图常常在字体到位之前就发生了。第一版四张卡片全是系统黑体，原因就在这里。

![图册第一页：9 款中文字体的真实渲染](/attachments/font-atlas-01.png)

第一页里，「澳声通注音库楷」带着注音符号，「快去写作业 CJK」是手写格子感，「游趣体」是卡通无衬线。这些不是风格标签，是能指着说的画面。

## 别用眼睛验收字体

最迷惑的一次：自检脚本说四款字体都加载成功，图上却全是同一种黑体。

两处 bug。一是分片文件名有两种长度，多数是 32 位十六进制，得意黑是 36 位；正则写死 32 位，截掉前四位，下载到的是一段 `{"error":"not_found"}`。二是卡片写成 `style="font-family:"fh-xxx",…"`，双引号把 HTML 属性截断，DOM 根本没应用字体，而 canvas 里用的是 JS 字符串，不受影响——自检和画面因此给出相反结论。

后来换了客观指标：用 canvas 量同一句话在四种字体下的渲染宽度。555.2、555.7、443.4、534.7，各不相同才说明生效。思源黑体和思源宋体只差 0.5，是 CJK 等宽（中日韩字符占同样宽度）造成的，不是没加载。

这条比字体本身有用：**能量化的判断，别留在形容词里。**

## 给 AI 的入口

站点自动生成 `/llms.txt`，这篇文章会进最近文章列表。要让模型直接读，用下面几个固定地址。

| 用途 | 地址 |
|---|---|
| AI 指令（纯文本） | `https://shawn2016.github.io/skills/font-chooser/SKILL.md` |
| 230 款结构化数据 | `https://shawn2016.github.io/skills/font-chooser/font_catalog.json` |
| 图册索引与逐页清单 | `https://shawn2016.github.io/skills/font-chooser/index.md` |
| 样张 01–15 | `https://shawn2016.github.io/attachments/font-atlas-01.png` … `-15.png` |
| 交互预览（输入任意文字） | `https://shawn2016.github.io/skills/font-chooser/gallery.html` |

给模型的指令可以写成一句话：读 `index.md` 的风格速查定位页码，打开对应 PNG，挑一款，报出「第 N 页 #M」和 id，再按 `SKILL.md` 的模板生成 link。

引用模板长这样，`<id>`、`<weight>`、`<cssFamily>` 一律查表得到，不猜：

```html
<link rel="stylesheet" href="https://duadu.cc/web/FontChan/api/font/<id>/<weight>/result.css">
<style>
  .title { font-family: "<cssFamily>", system-ui, sans-serif; font-weight: <weight>; }
</style>
```

清单里 `styleCn` 有 115 种细碎值（「窄黑」「注音楷体」之类），直接分组没法看。索引把它归并成 7 类：楷体 / 仿宋 32、手写 / 书法 24、圆体 / 可爱 23、宋体 / 衬线 21、黑体 / 无衬线 16、展示 / 标题 9、其他 5。速查只负责导航，具体字形一律看图。

## 失效的地方

诚实记一下这套东西不覆盖什么。

- **AI 直接生图**：字形由模型画出来，不由 CSS 控制，图册只能当风格提示词写进 prompt。
- **静态样张只覆盖固定那二十来个字**：换文案要重新生成，或者用[交互预览页](https://shawn2016.github.io/skills/font-chooser/gallery.html)（走远程 `unicode-range` 分片，支持任意文字）。
- **230 款里只有 130 款含中文字形**：拿 Anton 排中文会静默 fallback（浏览器找不到字形时退回系统字体），等于没选。
- **清单之外没有**：阿里巴巴普惠体查不到，得自备字体文件本地裁子集。
- **数据本身不干净**：`useCases` 有批量打标签痕迹，场景列只能当参考，判断以风格描述和图片为准。
- **下载字体文件本体需要 API Key**（邀请码），贴 link 不需要。字体是 OFL-1.1，可商用，保留原作者版权声明即可；个别字体另有「不得改名、不得售卖字体本身」的限制。

## 判据库

- 2026-11-12 选字体：形容词不可验收；一次选择必须同时交出「图片编号」和「引用代码」，用同一个 id 对齐。
- 2026-11-12 做样张：字体有没有生效别用眼睛判断，量渲染宽度；能量化的判断不要留在形容词里。
- 2026-11-12 给模型喂资料：结构化清单解决「能不能查到」，图片解决「敢不敢判断」，两种载体缺一不可。
