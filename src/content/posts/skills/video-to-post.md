今天下午 13:46，B 站上多了一条 4 分 06 秒的视频，标题叫《别一上来就让 AI 干活》。我把它交给一条转录流水线，想写成文章。

本地 Whisper 吐出 200 段，开头是「非常使用的使用 A 陣的小 Tips」，第 147 段是「你把他沉淀成了一个你的 SQL」。照这份稿子写下去，文章里会凭空多出一次数据库查询。

翻车点不在模型笨。是我把「转录完了」当成了「听懂了」。

## 听懂了没有交付物

派活给 AI 时，最省事的一句话是「你直接去办」。它回一句「好的」，我们就假定双方理解一致。等报销单提交上去、文章发布出去，才发现它把 1000 元的门槛理解成了别的东西。

这类错误有个共同形状：**执行之前，没有任何一份东西能让人指着说「这里理解错了」**。

所以这里要反过来说一次：**越想自动化，越要先造一份能被核对的复述。转录不是内容，是 AI 的第一次复述。**

这个判断有成立条件：任务要有可核对的产出，且错误代价可逆。报销提交、文章发布这类动作改不回去，人工得卡在最后一步，不能省。

视频里把这件事说成一个具体动作：派活时补一句「先别动手，用你自己的话说说我到底让你做什么」。同一条判断，换个助手、换段音频、换篇文章都还成立。

## 六次验收，每次交一样东西

把「先复述再动手」拆成流水线，每一步都要有一个能指着说的交付物。

| 环节 | 交出什么 | 没交出来就不能往下走 |
|---|---|---|
| 复述 | 转录稿 | 只有一句「我听懂了」 |
| 纠偏 | 术语核验表 | 音译错混进正文 |
| 记忆 | 一份 SKILL.md | 下次从零再教一遍 |
| 分工 | 各段工具的边界 | 让一个 bot 又转录又发布 |
| 陪跑 | 逐项验收记录 | 第一次就撒手 |
| 自动化 | 可重复触发的脚本 | 流程还靠人记着 |

这张表是方法，不是某个产品的功能列表。把 Grok Bot 换成别的助手、把 B 站换成播客、把 Whisper 换成另一套 ASR（自动语音识别），六行都得照样填。

检验办法沿用本站那篇《采集类文章写作框架》：把工具名全部替换掉，文章还成立吗？成立。它规定的是证据的形式，不是哪款音频模型。

## 今天这条链路怎么跑的

按上表的顺序说，不按工具清单说。

**复述。** 视频没有官方字幕（`subtitle.list` 是空的），只能下音频。`yt-dlp -f 30280` 加 Chrome 登录态，拿到 2.6 MB 的 m4a，246 秒。跑两路转录：本地 faster-whisper tiny 出 200 段，云端 ASR 出 5 段、按分钟切好。

两路的差别不是字数，是错法不一样。本地模型把英文专名听成中文音，云端把连读的词粘成一个。

**纠偏。** 列一张对照表，每个可疑词都要有出处：

| 本地 tiny | 云端 ASR | 正确写法 | 依据 |
|---|---|---|---|
| Grock Bolt | grokbot | Grok Bot | UP 主自己写的简介 |
| A 陣 / A 陈 | Agent | Agent | 简介 + 上下文 |
| Carser | Cursor | Cursor | 简介 |
| cloudcode | cloudcode | Claude Code | 上下文（专门改代码的工具） |
| SQL | skill | Skill | 上下文「沉淀成一个 skill」 |
| 妥妥姐老人谈 | 土豆姐 laurentanan | 土豆姐 Lauren Tan（@poteto） | 实搜：Grok Bot 工程负责人 |

六个词，五个靠 UP 主简介纠正，一个靠实搜。作者本人写下的简介比两路机器转录都可靠，这是今天最省事的一条经验。

![视频封面：别一上来就让 AI 干活](/attachments/video-to-post-cover.jpg)

**记忆。** 把这条链路写成 `SKILL.md`，本机一份，线上一份。线上一份不引用任何本地路径，外部模型打开链接就能照着做。

**分工。** 转录归 ASR，成文归写作框架，发布归 GitHub API。视频里说「别让 bot 自己改代码，改代码交给 Cursor」，落到我们这边是同一件事：不要让负责转录的环节顺手决定文章怎么写。

**陪跑。** 第一次跑完，逐项核对：frontmatter 对不对得上站点的 posts schema、禁用词是不是零命中、图片路径能不能打开、判据库有没有追加、发布后每个 URL 是不是 200。这些检查写到脚本里，也是给人看的验收单。

![六次验收的流水线：复述、纠偏、记忆、分工、陪跑、自动化](/attachments/video-to-post-flow.png)

**自动化。** 这一步今天没做。视频里给过一个具体的代价：让助手每 15 分钟跑一次，一天将近 100 次，每次都花钱；每小时或一天几次通常就够了。我们这条链路还停在手动触发，等同一条流程跑顺几次再说。

## 证据边界

诚实记一下哪些东西没覆盖。

- **两路转录都不是金标准。** 云端 ASR 把「Grok Bot 和 Muse」粘成了「grokbotmuse」，本地 tiny 把「一小时」听成「小声电话」。以作者原文为准，机器稿只用来补口播细节。
- **刚发布一小时，官方字幕还是空的。** 有字幕的视频可以省掉下载和转录，核验仍然不能省。
- **只覆盖口播。** 竖屏画面里演示的报销表单、按钮位置，转录拿不到，文章也不假装讲过。
- **英文专名是重灾区。** 本地 tiny 在这条 4 分钟视频里错了六个，和以前记录的实测（12 分钟视频 9 个专名全错）是同一个方向的问题。
